# CLAUDE.md

tokengraph is a GitHub-contribution-style heatmap of daily AI coding agent token usage (Claude Code, Codex CLI, Cursor, Gemini CLI, Cline, OpenCode, Kilo CLI, Copilot CLI, pi, Qwen Code, Goose). It is **local-first and has no server**: the CLI reads each agent's local logs, keeps a ledger on the machine, and publishes the README graph as SVG files to the user's own public GitHub gist; a secret gist holds every machine's ledger so machines merge and history survives a reinstall. Story cards (Instagram/TikTok PNGs) are rendered on the machine and handed to the phone with a QR code over the local network.

`docs/product.md` holds the vision and non-goals. Design notes: `docs/architecture.md`; per-agent log formats: `docs/agents/`.

## Commands

```bash
npm install
npx tsc --build                     # build packages/core + packages/cli
npx vitest run                      # all tests
npx vitest run packages/core/test/pricing.test.ts
npx vitest run -t "test name substring"
node packages/cli/dist/bin.js sync --local      # never touches the network
node packages/cli/dist/bin.js view --print
cd packages/cli && npm run build    # tsc, then esbuild bundle → packages/cli/bundle/bin.js (what npm ships)
cd packages/cli && npm pack
```

Vitest aliases `@tokengraph/core` to `packages/core/src`; the CLI at runtime resolves it through `dist/` — rebuild core (`npx tsc --build`) after changing it before running the CLI.

## Architecture

- **`packages/core`** — pure, dependency-free: token types and the weighted-token formula (`tokens.ts`), pricing with dated rate history (`pricing.ts`), model labels/makers/families/logos, allowed sources (`sources.ts`), per-user percentile levels and the SVG graph renderer (`levels.ts`, `graph.ts`, `graph-colors.ts`), graph days by family (`graph-days.ts`), the embed font (`embed-font.ts`, generated), the published SVG set (`published-graphs.ts`), story data (`story/`), the `Adapter` interface. No file or network I/O, no third-party imports. `.js` import suffixes (NodeNext).
- **`packages/cli`** — the `tokengraph` CLI (`view` default in a TTY, `login`, `logout`, `sync`, `readme`, `story`, `status [--json]`, `install-hook --agent <claude-code|cursor|codex|gemini-cli>`, `schedule`, `export`, `import cursor <csv|--fetch>`, `cursor <fetch|on|off>`, `uninstall [--purge]`). Adapters in `src/adapters/<agent>/` (see the per-agent notes below). `src/github/` talks to GitHub (HTTP client, device flow, auth via a stored token or the `gh` CLI). `src/publish/` builds machine files, finds or creates the two gists and publishes. `src/story/` renders cards with Satori + resvg-wasm (assets in `packages/cli/assets/`); `src/share/` is the QR hand-off server. `src/tui/` is the dependency-free terminal view. State lives in `~/.tokengraph/` (`$TOKENGRAPH_HOME`): `config.json` (machine id, GitHub login and auth, gist ids, graph colours, `agentRoots` = agent folders remembered from the environment of earlier runs; mode 0600), `state.json` ledger (v3, keyed by source and pricing tier), `machines.json` (other machines' files from the last publish, for offline use), `cursor-events.jsonl`, `cursor-import.jsonl` and `cursor-account-<accountKey>.jsonl` (Cursor usage; never pruned), `cursor-fetch.json` (Cursor fetch state, no secrets). `uninstall --purge` deletes only the files listed in `OWN_FILES` (and its temp-file pattern) in `commands/uninstall.ts`, and keeps anything else in the folder.
- Adapter sources (every one scans the union of its default, environment and remembered roots: `src/agent-roots.ts`, `adapters/<agent>/roots.ts`): `claude-code` streams `~/.claude/projects/**/*.jsonl` and `transcripts/*.jsonl` (respects `CLAUDE_CONFIG_DIR`) plus Claude Desktop's Code/Cowork sessions under its app data (`local-agent-mode-sessions`, `claude-code-sessions`); `codex` streams `$CODEX_HOME/{sessions,archived_sessions}/**/*.jsonl`; `cursor` reads `~/.tokengraph/cursor-events.jsonl` written by `tokengraph cursor-hook` plus `cursor-import.jsonl` from `tokengraph import cursor <csv>` (imported rows count only before the first hook event); the account history fetched from cursor.com (`adapters/cursor/fetch*.ts`, `credentials.ts`) is not read by the adapter but kept in the ledger's `accounts.cursor`; `gemini-cli` streams `*/chats/**` under `${GEMINI_CLI_HOME:-~}/.gemini/tmp` and `~/.cache/.gemini/tmp`; `cline` reads classic `ui_messages.json` and SDK `*.messages.json`; `opencode` reads `opencode*.db` (`node:sqlite`) and the pre-1.2 `storage/` JSON tree; `kilo` reads `kilo*.db` (`$KILO_DB`, same reader as OpenCode); `copilot-cli` reads `~/.copilot/session-store.db` (`$COPILOT_HOME`); `pi` streams `~/.pi/agent/sessions` (`$PI_CODING_AGENT_DIR`); `qwen-code` streams `~/.qwen/projects` chats and `subagents/` plus Qwen's own `usage/token-usage-*.jsonl` ledger, taking per day whichever source has more weighted tokens (`$QWEN_HOME`, `$QWEN_RUNTIME_DIR`); `goose` reads `sessions.db` `usage_ledger` under the Goose data dir (`$XDG_DATA_HOME`, `$GOOSE_PATH_ROOT`).

### Invariants that are easy to break

- **Dedup by `message.id`** (Claude Code), **by `response_id` across files** (Codex), **by message `id` across files** (Gemini CLI), **classic `taskId + ts`, SDK message `id`** (Cline; skip the `claude-code` provider, imported sessions, legacy-copy metrics, `deleted_api_reqs`, `*.compaction.json`), **message id plus fork fingerprint** (OpenCode; step-finish parts are the request unit; pre-1.3.16 rule in `docs/agents/opencode-usage.md`), **the same for Kilo CLI** (shared code, Kilo's own thresholds: 7.2.6, no AI SDK 6 window; `docs/agents/kilo-usage.md`), **session id plus row id** (Copilot CLI; `session-store.db` `assistant_usage_events`, one row per request, input includes cache so fresh input = input - cache read - cache write; `reasoning_tokens` is never added to output; `docs/agents/copilot-cli-usage.md`), **provider + `responseId` across files** (pi; per-request JSONL, `input` is already exclusive of cache, `reasoning` is never added to output, forked sessions copy entries; `docs/agents/pi-usage.md`), **`uuid` across files, ledger `id` across files** (Qwen Code; the usage ledger, schemaVersion 1 only, also holds the memory extractor's requests and is never summed with the chats; `usageMetadata.promptTokenCount` includes cache and, on the Anthropic protocol, cache creation, so fresh input = prompt - cached, output = max(candidates, total - prompt) and `thoughtsTokenCount` is never added; `/branch` copies records verbatim; subagent transcripts under `subagents/` carry no model, the `agent-<id>.meta.json` sidecar does; `docs/agents/qwen-code-usage.md`), **session id + ledger row id + timestamp** (Goose; `sessions.db` `usage_ledger`, one row per provider call, every existing database is read and a copy of one collapses, `input_tokens` includes cache so fresh input = input - cache read - cache write and a negative result is skipped as unknown; `carried_forward` rows are skipped; sessions of wrapper providers whose agent has its own adapter (`claude-code`, `claude-acp`, `codex`, `codex-acp`, `gemini-cli`, `cursor-agent`, `copilot-acp`, `pi-acp`) are skipped; `docs/agents/goose-usage.md`). `<synthetic>` model is excluded. Never count usage another adapter already counts (Cline, OpenCode and Kilo skip the `claude-code` provider).
- **Adapters scan the union of default, env and remembered roots, deduped by realpath.** A root is recorded in `config.json` `agentRoots` whenever a command runs with an override in its env (`rememberAgentRoots`); resolvers take an injected `{ platform, env, home }`, never `process.env` directly; a missing root is skipped silently.
- **Within one machine totals only grow** (ledger max-merge, also against the machine's own file in the data gist). **Across machines usage is summed.** Never sum a machine with itself; `logout` keeps the machine id.
- **A Cursor account is not a machine.** The history fetched from cursor.com is account-level (every machine and surface). It lives in the ledger and machine file as `accounts.cursor[accountKey] = { coveredThrough, days }`, and every consumer (graph, view, story, `export --all-machines`, `status`, publish) combines it through `combineMachineUsage` in `packages/core/src/combine-usage.ts` and nowhere else: per account key max across machines, summed across accounts; the `cursor` source (hook plus import) is ignored for local days before the newest `coveredThrough`; from that day on, per model, max(account, summed `cursor` source). Never sum an account with itself, never add it on top of hook events.
- **Never store, log, print or publish the Cursor token, the cookie, the user id or the e-mail**, and never echo a response body or put one in an error message. The token is read from `state.vscdb` (read-only, one row) for one request and sent only to `cursor.com` / `www.cursor.com` (redirects checked by hand). `accountKey` (first 16 hex of the SHA-256 of the normalised user id) is the only trace of the account. Tests use fixture databases and a local fake server, never the real Cursor folder or cursor.com.
- **Hour data is local only, never in machine files or gists.** `hours` and `accountHours` live in `state.json`; the machine file builder lists `sources` and `accounts` explicitly. Hours are summed per request-weighted tokens and are display-only; Cursor hours follow the same covered-day rule as the daily combine (`combineMachineHours`). `export --hours` is this machine only.
- **Weighted tokens** = `input + output + cache_creation + 0.1 × cache_read`; sum per day first, then weight.
- **Cache-write 5m/1h split is `null` when unknown, never 0.** Unpriced models are unknown, never $0.
- **Pricing tier is a key dimension**; pricing changes append a new `effectiveFrom` entry, never edit a rate. Only models whose vendor publishes a list price are priced (Anthropic, OpenAI, Google, xAI, Cursor Composer); open-weight, retired, preview-without-a-price and router ids stay unpriced, never mapped to a successor. The long-context threshold is per model (`longContext.thresholdTokens`, read through `longContextThreshold`), and `fastMultiplier: null` means the vendor publishes no fast row.
- **Renaming a model id or changing a tier rule needs a ledger migration once released.** The ledger max-merges per source/date/model/tier and never prunes a key, so tokens recorded under an old name or tier would stay and the new one would be added beside them.
- **New adapter/source:** also add it to `KNOWN_SOURCES` in `packages/core/src/sources.ts`.
- **The view never publishes.** Only `sync` (manual, hook or schedule), `login` and `readme --colors` talk to GitHub. `status`, `view`, `story`, `export`, `import <file>` are offline. The only other network call is the Cursor fetch (`sync` without `--local`, `cursor fetch`, `import cursor --fetch`) to cursor.com, on by default when Cursor is signed in and off with `tokengraph cursor off`.
- **The public graph gist holds only SVGs and a README** — family colours and names, never model ids or per-model counts (only daily totals). Those live only in the secret data gist.
- **Codex `notify` is single-valued**; never overwrite one that is not ours.
- **The Claude Code and Gemini CLI hooks must return instantly** (runs hidden `hook-sync`, which spawns a detached `sync`).
- **Hook, script and asset paths resolve through `bin-path.ts`** (`binPath()`, `assetsDir()`), never `import.meta.url` in a command: inside the bundle every module shares one URL.
- **Tests never touch the real `~/.tokengraph` or the real GitHub.** Network tests use `test/fake-github.ts`. Tests run with a throwaway `HOME` (and agent/XDG folders) from `packages/cli/test/setup-home.ts`, wherever vitest is started: the package `vitest.config.ts` files reuse the root config, and `configHome()` throws under vitest without `TOKENGRAPH_HOME`.
- **`canonicalModelId`** is the only place provider decorations are stripped. **Cursor model slugs are normalised** by `normalizeCursorModel`. The Cursor event file, the Cursor import file and the fetched account files are never pruned.
- **Per-model colour = model family, never agent.** Hue is never the only channel.
- **Colour levels are per-user percentiles** (p25/p50/p75 of the user's own non-zero days).
- **The QR share server** binds to one private LAN address, serves only from memory under a random token, and always stops.
